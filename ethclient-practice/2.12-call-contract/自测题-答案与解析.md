## Q1：eth_call 和 eth_sendRawTransaction 分别对应哪类合约调用？在 Gas、私钥、状态修改、返回方式上各有什么不同？

**原题：**  
eth_call 和 eth_sendRawTransaction 分别对应哪类合约调用？在 Gas、私钥、状态修改、返回方式上各有什么不同？

**你的解答：**  
eth_call 是读取，eth_sendRawTransaction 是写入。  
eth_call：不消耗 gas，不读取私钥，不修改状态，立即返回。  
eth_sendRawTransaction：消耗 gas，修改链上状态，需要私钥，返回需要等待确认。

**参考答案：**  
- **对应调用**：eth_call 对应**读取**（view/pure 等只读调用），eth_sendRawTransaction 对应**写入**（会改状态的交易）。  
- **eth_call**：不消耗 Gas、不需要私钥、不修改链上状态、立即返回结果。  
- **eth_sendRawTransaction**：消耗 Gas、需要私钥签名、会修改链上状态、返回交易哈希，需等待被打包/确认后才算「完成」。

**判定：** ✅ 正确（含义完整；表述上「不读取私钥」更常见写成「不需要私钥」）

**得分：** 1.0 / 1

## Q2：调用 abigen 生成的合约的 view 函数时，第一个参数通常传 nil，这个 nil 代表什么？如果想在指定区块号上查询，该怎么写？

**原题：**  
调用 abigen 生成的合约的 view 函数时，第一个参数通常传 nil，这个 nil 代表什么？如果想在指定区块号上查询，该怎么写？

**你的解答：**  
nil 表示使用默认的 callOpts。定义 &bind.CallOpts 对象，字段 BlockNumber 指定区块号。

**参考答案：**  
- **nil**：表示使用**默认的 CallOpts**（等价于 `&bind.CallOpts{}`），即：不指定区块、不用 pending 状态、用默认 context。  
- **指定区块号**：构造 `&bind.CallOpts{ BlockNumber: big.NewInt(区块号) }`，把该对象作为 view 调用的第一个参数传入即可。

**判定：** ✅ 正确

**得分：** 1.0 / 1

## Q3：调用写函数前为什么要用 bind.NewKeyedTransactorWithChainID 创建 auth？如果要在交易里附带 1 ETH，应该设置 auth 的哪个字段？

**原题：**  
调用写函数前为什么要用 bind.NewKeyedTransactorWithChainID 创建 auth？如果要在交易里附带 1 ETH，应该设置 auth 的哪个字段？

**你的解答：**  
因为需要通过 privateKey 和 chainId 获取交易认证器。Value 字段。

**参考答案：**  
- **为什么要创建 auth**：写函数需要**签名交易**，auth 里包含从私钥和 ChainID 派生的签名信息；`NewKeyedTransactorWithChainID` 用私钥和 ChainID 生成符合 EIP-155 的**交易认证器**，后续写调用会用这个 auth 自动填 from、签名等。  
- **附带 1 ETH**：设置 **Value** 字段，例如 `auth.Value = big.NewInt(1000000000000000000)`（1 ETH = 10^18 wei）。

**判定：** ✅ 正确

**得分：** 1.0 / 1

## Q4：发送写函数的交易后，为什么不能马上得到「执行结果」？要拿到交易是否成功、用了多少 Gas，应该用什么方式？

**原题：**  
发送写函数的交易后，为什么不能马上得到「执行结果」？要拿到交易是否成功、用了多少 Gas，应该用什么方式？

**你的解答：**  
因为发送交易，要打包到区块，广播给验证者，需要时间。可以到 sepolia.etherscan 输入交易 hash 查看。

**参考答案：**  
- **为什么不能马上得到结果**：写函数发的是**交易**，需要被矿工/验证者打包进区块并确认，有网络和出块延迟，所以 RPC 只能先返回交易哈希，不能立即给出链上执行结果。  
- **用什么方式拿到成功与否和 Gas**：  
  1. **代码里**：用 `bind.WaitMined(ctx, client, tx)` 等回执后再看 `receipt.Status`、`receipt.GasUsed`；或轮询 `client.TransactionReceipt(ctx, tx.Hash())` 拿到 receipt 后同样看 Status 和 GasUsed。  
  2. **浏览器**：到区块浏览器（如 sepolia.etherscan.io）用交易 hash 查看，也是一种方式。

**判定：** ⚠️ 部分正确（「为什么」答对；「用什么方式」只写了浏览器，未写代码里的 WaitMined/TransactionReceipt）

**得分：** 0.8 / 1

## Q5：交易回执里的 receipt.Status 为 0 和 1 分别表示什么？交易 revert 时你会看到哪个值？

**原题：**  
交易回执里的 receipt.Status 为 0 和 1 分别表示什么？交易 revert 时你会看到哪个值？

**你的解答：**  
0 代表失败，1 代表成功。revert 会看到 0。

**参考答案：**  
- **Status**：`1` 表示交易**成功**执行，`0` 表示**失败**（如 revert、out of gas 等）。  
- **revert 时**：链上会把该笔交易记为失败，所以 **receipt.Status == 0**。

**判定：** ✅ 正确

**得分：** 1.0 / 1

## Q6：在不使用 abigen 的前提下，要手动构造对 setItem(bytes32,bytes32) 的调用数据，函数选择器是怎么算出来的？

**原题：**  
在不使用 abigen 的前提下，要手动构造对 setItem(bytes32,bytes32) 的调用数据，函数选择器是怎么算出来的？（可以说思路或公式，不需要写完整代码。）

**你的解答：**  
解析 ABI -> 打包函数调用数据。

**参考答案：**  
- **函数选择器**：取**函数签名**（如 `"setItem(bytes32,bytes32)"`）的 **Keccak256 哈希的前 4 字节**，即 `selector = Keccak256("setItem(bytes32,bytes32)")[:4]`。  
- 若用 ABI：可先解析 ABI，再用 `abi.Pack("setItem", key, value)` 打包，其内部会按上述规则算选择器并拼上参数；但「选择器怎么算」的公式就是 Keccak256(签名)[:4]。

**判定：** ⚠️ 部分正确（提到了用 ABI 解析再打包，是可行做法，但未写出选择器本身的**计算公式**：Keccak256(函数签名)[:4]）

**得分：** 0.5 / 1

## Q7：手动发合约调用交易时，除了目标合约地址和 data，通常还需要从链上查询哪些信息（至少写出两个）才能正确构造并发送交易？

**原题：**  
手动发合约调用交易时，除了目标合约地址和 data，通常还需要从链上查询哪些信息（至少写出两个）才能正确构造并发送交易？

**你的解答：**  
nonce, gasPrice。

**参考答案：**  
- **nonce**：发送地址的当前/待处理 nonce，用于组交易，一般用 `client.PendingNonceAt(ctx, from)` 获取。  
- **gasPrice**（或 EIP-1559 下的 maxFeePerGas / maxPriorityFeePerGas）：用于设定 gas 单价，常通过 `client.SuggestGasPrice(ctx)` 或类似接口获取。  
- 可选：GasLimit 也可按需估算或设固定值，链上不一定要「查」，但构造交易时需要。

**判定：** ✅ 正确（nonce、gasPrice 均为必须从链上/节点获取的典型项）

**得分：** 1.0 / 1

## Q8：CallOpts 和 TransactOpts 分别用在什么场景？它们各自可以配置的常见选项有哪些（各举 1～2 个即可）？

**原题：**  
CallOpts 和 TransactOpts 分别用在什么场景？它们各自可以配置的常见选项有哪些（各举 1～2 个即可）？

**你的解答：**  
CallOpts 用在读取，TransactOpts 用在交易。  
CallOpts 可以配置的选项：BlockNumber, Pending, Context。  
TransactOpts 可以配置的选项：GasPrice, GasLimit, Value。

**参考答案：**  
- **CallOpts**：用在**只读调用**（view/pure 或 eth_call），指定在哪个区块/是否 pending、context 等。常见选项：**BlockNumber**（查询指定区块）、**Pending**（是否用 pending 状态）、**Context**（超时/取消）。  
- **TransactOpts**：用在**写交易**（发送并签名交易），指定 gas、value 等。常见选项：**GasPrice**、**GasLimit**、**Value**（随交易发送的 ETH）等。

**判定：** ✅ 正确

**得分：** 1.0 / 1
